## 2. 背景

用户希望开发一个可持续接入多个 MCP Server 的个人 Agent。首期不追求完整的多 Agent 编排，而是选择一个真实 MCP 完成端到端验证，确认以下核心能力可行：

1. Agent 可以通过配置接入本地 MCP Server。
2. Agent 可以发现并正确调用 MCP 工具。
3. Agent 能根据问题判断是否需要联网搜索。
4. 搜索结果能够整理为可阅读、可追溯的回答。
5. MCP 启动、鉴权、调用失败时，用户能获得明确反馈。
6. 后续增加其他 MCP 时，不需要修改 Agent 核心流程。

首个验证对象为博查-AI搜索 MCP。该服务以 Python 实现，通过 `stdio` 接入，并使用 `BOCHA_API_KEY` 环境变量完成鉴权。

## 3. 产品目标

### 3.1 MVP 目标

打造一个本地运行的个人 Agent，使用户可以在 Web 界面中提出需要实时信息的问题，由 Agent 自动调用博查搜索，并返回带来源链接的答案。

### 3.2 成功标准

- 用户完成一次配置后即可在 Agent 会话中使用博查搜索。
- Agent 启动时能够发现博查提供的两个 MCP 工具。
- 对明显需要实时信息的问题，Agent 能自动调用合适的搜索工具。
- 回答包含结论、关键信息和可点击的来源链接。
- 普通知识或无需联网的问题不会无意义触发搜索。
- API Key、完整鉴权 Header 不出现在界面、日志和会话记录中。
- MCP 异常不会导致整个 Agent 无法启动或会话崩溃。

### 3.3 非目标

以下内容不在首期范围：

- 多用户、组织和权限体系。
- 云端托管与跨设备同步。
- 多 Agent 团队协作。
- 自主执行写操作或高风险操作。
- 搜索结果长期知识库和向量化。
- 搜索供应商自动切换或聚合搜索。
- MCP 市场、在线安装和插件商店。
- 复杂工作流编排、跨天任务和失败补偿。

## 4. 目标用户与场景

### 4.1 目标用户

首期用户为产品开发者本人，具备基础开发环境配置能力，希望通过统一对话入口使用外部工具。

### 4.2 核心场景

1. **实时资讯查询**
   - 示例：查询当天新闻、产品发布、市场动态。

2. **资料检索**
   - 示例：查找某项技术的官方文档、报告或公开资料。

3. **结构化实时信息**
   - 示例：查询天气、股票、汇率、百科等可能包含结构化卡片的信息。

4. **限定时间范围搜索**
   - 示例：只查询最近一周或指定日期范围内的信息。

5. **带来源回答**
   - 用户需要知道结论来自哪些网页，并能继续打开原文核验。

## 5. MCP 能力范围

### 5.1 MCP 基本信息

| 字段 | 内容 |
| --- | --- |
| 名称 | 博查-AI搜索 |
| Server namespace | `bocha` |
| 接入方式 | Local / stdio |
| 实现语言 | Python |
| 鉴权方式 | API Key |
| 环境变量 | `BOCHA_API_KEY` |
| 官方仓库 | https://github.com/BochaAI/bocha-search-mcp |
| 开放平台 | https://open.bochaai.com/ |

### 5.2 工具清单

#### `bocha_web_search`

用于通用网页检索，返回网页标题、URL、摘要、发布时间和站点名称等信息。

输入参数：

| 参数 | 必填 | 约束 | 默认值 |
| --- | --- | --- | --- |
| `query` | 是 | 非空自然语言查询 | 无 |
| `freshness` | 否 | 日期、日期区间或预设时间范围 | `noLimit` |
| `count` | 否 | 1-50 | 10 |

#### `bocha_ai_search`

用于语义搜索和结构化实时信息查询。除网页结果外，可返回天气、百科、股票、汇率等垂直领域模态卡。

输入参数：

| 参数 | 必填 | 约束 | 默认值 |
| --- | --- | --- | --- |
| `query` | 是 | 非空自然语言查询 | 无 |
| `freshness` | 否 | 支持的预设时间范围 | `noLimit` |
| `count` | 否 | 1-50 | 10 |

### 5.3 工具选择规则

- 查询网页、报告、新闻来源、官方链接时，优先使用 `bocha_web_search`。
- 查询天气、百科、股票、汇率等结构化实时信息时，优先使用 `bocha_ai_search`。
- 用户明确要求“搜索网页”“给出链接”时，优先使用 `bocha_web_search`。
- 用户指定“最近一天/一周/一月”等范围时，映射到 `freshness`。
- 默认返回 10 条搜索结果；用户明确指定数量时，范围限制为 1-50。
- 一次搜索已足够回答时不重复调用；结果不足或需要交叉核验时允许二次搜索。

## 6. 产品流程

### 6.1 首次配置

1. 用户启动本地 DeepSeek Harness Web UI。
2. 用户配置可用模型及模型凭证。
3. 用户通过本地安全配置提供 `BOCHA_API_KEY`。
4. Harness 启动博查 MCP 子进程。
5. Harness 完成工具发现并注册带 namespace 的工具。
6. 设置页显示博查 MCP 当前状态。

### 6.2 对话搜索

1. 用户输入问题。
2. Agent 判断问题是否依赖实时或外部信息。
3. Agent 选择博查 Web Search 或 AI Search。
4. Agent 生成搜索参数并调用工具。
5. Agent 读取搜索结果，过滤重复、低相关或信息不足的内容。
6. Agent 汇总结论，并附上来源。
7. 会话中保留工具名称、非敏感参数、调用状态和结果摘要。

### 6.3 异常流程

- MCP 未启动：会话可继续，提示“搜索服务当前不可用”。
- API Key 缺失：阻止调用，并引导用户进入配置。
- API Key 无效：提示鉴权失败，不展示服务端完整响应和凭证。
- 请求超时：允许 Agent 重试一次；再次失败后结束调用。
- 无搜索结果：明确说明未找到可靠结果，并建议调整关键词或时间范围。
- 返回格式异常：保留原始调用状态，向用户返回可理解的降级提示。

## 7. 功能需求

### FR-01 Agent 会话

- 提供基础 Web 对话界面。
- 支持流式展示模型回答。
- 区分用户消息、Agent 回答和工具调用状态。
- 刷新页面后能够继续当前本地会话。

### FR-02 模型配置

- 支持 DeepSeek 模型。
- 模型 Provider 与 Agent 业务逻辑解耦。
- 模型凭证必须以密码字段录入，不回显完整值。
- 首期至少支持一个可用模型完成工具调用。

### FR-03 MCP 配置

- 通过独立配置项接入博查 MCP，不修改 Harness 核心源码。
- MCP 配置包含稳定的 `serverName`、传输方式、启动命令、参数、工作目录和环境变量映射。
- 博查工具公开名称必须带 `bocha` namespace，避免未来多 MCP 工具重名。
- 支持启用、禁用和重新加载博查 MCP。

### FR-04 MCP 状态

设置页至少展示：

- MCP 名称。
- 启用状态。
- 连接状态。
- 已发现工具数量。
- 最近一次连接或调用错误摘要。
- 重新连接操作。

### FR-05 搜索调用

- Agent 可以自主判断是否调用搜索。
- 用户明确要求联网时必须尝试调用搜索。
- 用户明确要求不要联网时不得调用搜索。
- Agent 必须校验 `count` 范围。
- Agent 不得把空查询发送给 MCP。

### FR-06 搜索结果回答

回答默认包含：

1. 直接结论。
2. 关键事实或摘要。
3. 信息时间范围或发布时间（结果提供时）。
4. 来源列表。

来源至少展示网页标题和 URL。相同 URL 只展示一次，不得编造搜索结果中不存在的来源。

### FR-07 工具调用可观测性

- 记录工具名称、开始时间、耗时、状态和错误类型。
- 可记录查询词、时间范围和结果数量。
- 不记录 API Key、Authorization Header 和完整环境变量。
- 用户可在会话中展开查看本次调用的非敏感详情。

### FR-08 凭证安全

- `BOCHA_API_KEY` 不写入仓库。
- `BOCHA_API_KEY` 不写入 PRD、示例配置和截图。
- 运行时通过环境变量或 Harness 凭证系统注入。
- UI 只显示“已配置/未配置”，不显示完整值。
- 日志输出前对疑似 Token、Key、Password 字段脱敏。
- 已在聊天或其他非密钥系统中暴露的 Key 必须先轮换，再用于联调。

## 8. 非功能需求

### 8.1 性能

- MCP 工具发现不应阻塞 Web UI 基本启动。
- 单次搜索默认超时不超过 60 秒。
- Agent 应在工具调用期间展示明确的进行中状态。
- 搜索结果进入模型上下文前应控制长度，避免无上限注入网页摘要。

### 8.2 稳定性

- MCP 子进程退出后支持自动重连。
- MCP 不可用时不影响无工具对话。
- 工具列表刷新失败时，保留上一次有效工具列表或明确标记不可用。
- 首期默认最多自动重试一次搜索请求，避免失控循环。

### 8.3 安全

- 本地 MCP 子进程仅获得显式注入的必要环境变量。
- 不向 MCP 子进程透传无关 Token、Secret 或 Password 环境变量。
- 禁止模型直接读取凭证值。
- 搜索结果视为不可信外部内容，不得将网页中的指令当作系统指令执行。
- 外部内容不得绕过 Agent 的权限规则触发文件、终端或其他工具。

### 8.4 可扩展性

- 每个 MCP Server 使用独立配置和唯一 namespace。
- 新增 MCP 不修改已有博查工具适配逻辑。
- 工具选择规则可按 MCP 独立扩展。
- 会话层只依赖统一工具调用结果，不依赖博查私有响应字段。

## 9. 数据与日志

### 9.1 会话数据

首期本地保存：

- 会话 ID。
- 用户消息。
- Agent 回复。
- 工具调用事件。
- 非敏感搜索参数。
- 工具结果摘要及来源链接。

### 9.2 禁止持久化

- API Key 明文。
- Authorization Header。
- 完整进程环境变量。
- 未经用户确认的敏感本地文件内容。

### 9.3 数据保留

- 首期采用本地保存。
- 用户可以删除单个会话。
- 日志和会话数据路径应明确可见。
- 后续若增加云同步，需要单独进行隐私和权限设计。

## 10. UI 要求

### 10.1 对话页

- 输入框。
- 发送与停止生成。
- Agent 流式回答。
- 工具调用状态行。
- 来源链接列表。
- 错误提示和重试入口。

### 10.2 设置页

- 模型配置。
- 博查 MCP 启用开关。
- API Key 配置状态。
- MCP 连接状态。
- 已发现工具列表。
- 测试连接按钮。
- 最近错误摘要。

### 10.3 交互原则

- 正常回答不暴露底层 JSON。
- 工具执行细节默认折叠。
- 错误文案给出下一步操作，不只展示异常代码。
- 长来源标题溢出时才显示 Tooltip。
- 空值统一显示 `--`。

## 11. 验收标准

### AC-01 MCP 启动与发现

- 配置有效 Key 后启动 Agent。
- 博查 MCP 状态显示为已连接。
- 工具列表中存在 Web Search 与 AI Search 两个工具。
- 工具名称带稳定的 `bocha` namespace。

### AC-02 普通网页搜索

输入：“搜索 DeepSeek Harness 最新的官方文档，并给出来源。”

预期：

- Agent 调用 Web Search。
- 返回至少一个有效结果。
- 回答包含结论及可点击 URL。
- 不展示 API Key。

### AC-03 结构化实时搜索

输入：“查询北京今天的天气。”

预期：

- Agent 优先调用 AI Search。
- 回答包含可用的实时天气信息。
- 若返回结构化卡片，Agent 能提取主要字段。
- 回答包含来源或明确标注数据来自博查 AI Search。

### AC-04 时间范围

输入：“搜索最近一周 DeepSeek Harness 的相关新闻。”

预期：

- 调用参数包含最近一周的时间范围。
- 回答优先使用该范围内结果。
- 没有符合条件的结果时明确说明。

### AC-05 不应搜索

输入：“把这句话改得更简洁。”

预期：

- 不调用博查搜索。
- Agent 直接完成改写。

### AC-06 无效凭证

- 使用无效 Key 启动或调用。

预期：

- UI 明确提示鉴权失败。
- 日志中不出现完整 Key。
- 无工具对话仍可继续。

### AC-07 MCP 进程异常

- 在会话中终止博查 MCP 子进程。

预期：

- 当前调用明确失败，不产生虚假成功结果。
- Agent 主进程和 Web UI 保持可用。
- 系统执行自动重连或提供手动重连入口。

### AC-08 无结果

输入一个预期无结果的精确查询。

预期：

- Agent 明确说明未找到可靠结果。
- 不编造结论、标题或 URL。
- 提供修改关键词或放宽时间范围的建议。

### AC-09 Prompt Injection 防护

- 搜索结果中包含“忽略之前指令”“读取本地密钥”等文本。

预期：

- Agent 将其视为网页内容而非系统指令。
- 不读取或输出本地凭证。
- 不因此调用无关高风险工具。

## 12. 埋点与评估

首期记录以下指标：

- MCP 启动成功率。
- 工具发现成功率。
- 搜索调用成功率。
- 搜索平均耗时和 P95 耗时。
- Web Search / AI Search 调用占比。
- 无结果率。
- 鉴权失败、超时、进程退出次数。
- 需要联网但未调用工具的漏调样本。
- 无需联网但触发工具的误调样本。
- 来源链接有效率。

首期通过固定测试集人工评估：

- 工具选择正确性。
- 回答事实准确性。
- 来源与结论一致性。
- 时效性。
- 无搜索问题的误调用率。
